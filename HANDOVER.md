# ApeWorker SMM — Документация по передаче проекта (Handover Guide)

Этот документ содержит исчерпывающее руководство по развертыванию, настройке и поддержке проекта **ApeWorker SMM** для новой команды разработки и эксплуатации.

---

## 1. Архитектура и стек контейнеров

Вся инфраструктура проекта полностью упакована в Docker и управляется через `docker-compose.yml`:

| Сервис | Контейнер | Назначение | Порт (локальный) |
| :--- | :--- | :--- | :--- |
| **frontend** | `apeworker_frontend` | Next.js 16 (App Router, Tailwind CSS, Keycloak Auth) | `127.0.0.1:3000` |
| **backend** | `apeworker_backend` | FastAPI (REST API, SQLite/SQLAlchemy, Celery dispatcher) | `127.0.0.1:8000` |
| **celery_worker** | `apeworker_celery` | Фоновый воркер: загрузка видео, наложение плашек (FFmpeg), автопостинг | — |
| **telegram_bot** | `apeworker_bot` | Aiogram 3: бот для приема ссылок, управления и уведомлений | — |
| **redis** | `apeworker_redis` | Очередь задач Celery и кэширование настроек | `127.0.0.1:6379` |
| **keycloak** | `apeworker_keycloak` | Аутентификация, SSO и управление сессиями пользователей | `127.0.0.1:8080` |

Все данные хранятся на хосте в каталоге `./data/`:
- `./data/uploads/app.db` — основная SQLite база данных (видео, расписания, роли, настройки).
- `./data/uploads/videos/` — скачанные исходные видео.
- `./data/uploads/watermarks/` — файлы плашек и оверлеев.
- `./data/keycloak/` — персистентное хранилище Keycloak.

## 2. Быстрый запуск на новом сервере (3 шага)

### Требования к серверу:
- Ubuntu 22.04 / 24.04 LTS (рекомендуется 2–4 CPU, 4–8 GB RAM).
- Установленные `docker` и `docker compose` (Docker Engine 24+).
- Установленный `git`.

### Шаг 1. Клонирование репозитория
```bash
git clone https://github.com/God3illa/apeworker_smm.git
cd apeworker_smm
```

### Шаг 2. Создание файла переменных окружения
```bash
cp .env.example .env
```
*(Все параметры уже имеют безопасные значения по умолчанию. Токены и ключи можно указать сразу в `.env` либо позже через веб-интерфейс).*

### Шаг 3. Запуск контейнеров
```bash
docker compose up -d --build
```

Проверить статус работы всех сервисов:
```bash
docker compose ps
```

## 3. Настройка API-ключей и сервисов через Веб-интерфейс

В проект встроен удобный графический интерфейс управления конфигурацией. Вам **не требуется** вручную менять конфиги на сервере.

1. Откройте панель управления в браузере (по вашему домену или `http://SERVER_IP:3000`).
2. В боковом меню перейдите: **Settings → API & Integrations** (`/settings/integrations`).
3. Заполните необходимые ключи:
   - **Upload Post API Key** — ключ сервиса [upload-post.com](https://upload-post.com) для автопостинга в соцсети (Instagram, TikTok, YouTube Shorts). Доступна кнопка **«Проверить связь»**.
   - **TELEGRAM_BOT_TOKEN** — токен Telegram-бота, полученный у [@BotFather](https://t.me/BotFather). Доступна кнопка **«Проверить бота»**.
   - **TELEGRAM_ALLOWED_USERS** — список Telegram ID пользователей через запятую (например, `123456789, 987654321`), которым разрешен доступ к боту. Если оставить пустым — бот отвечает всем.
   - **GEMINI_API_KEY** — ключ Google Gemini API (модель `gemini-1.5-flash` из [Google AI Studio](https://aistudio.google.com)) для умного рерайтинга хуков, названий и хештегов.
   - **DASHBOARD_URL** — публичный адрес сайта (например, `https://your-domain.com`) для ссылок в сообщениях бота.
4. Нажмите **«Сохранить изменения»**. Настройки сразу применятся во всех контейнерах без перезагрузки.

## 4. Перенос существующих данных (Опционально)

Если требуется передать проект с уже накопленной базой данных, историей и пользователями:
1. **На старом сервере:** сделайте архив папки `./data/`:
   ```bash
   tar -czvf apeworker_data_backup.tar.gz /var/www/apeworker_smm/data
   ```
2. **На новом сервере:** распакуйте архив в корень проекта перед запуском `docker compose up -d`:
   ```bash
   tar -xzvf apeworker_data_backup.tar.gz -C /var/www/apeworker_smm/
   ```

Если же проект запускается «с чистого листа» — делать это не нужно, контейнеры сами инициализируют чистую базу при первом запуске.

## 5. Настройка Nginx и доменных имен

Для работы в production перед контейнерами на сервере устанавливается Nginx в качестве Reverse Proxy с SSL-сертификатами Let's Encrypt:

- `your-domain.com` → проксирует на `127.0.0.1:3000` (Frontend) и `/api/` на `127.0.0.1:8000` (Backend).
- `auth.your-domain.com` (опционально) → проксирует на `127.0.0.1:8080` (Keycloak).

Пример конфигурации Nginx доступен в системных скриптах или настраивается стандартным `proxy_pass http://127.0.0.1:3000`.

## 6. Полезные команды для обслуживания

```bash
# Просмотр логов бэкенда в реальном времени
docker compose logs -f backend

# Просмотр логов воркера задач публикации
docker compose logs -f celery_worker

# Просмотр логов Telegram-бота
docker compose logs -f telegram_bot

# Перезапуск одного конкретного сервиса
docker compose restart frontend

# Полная остановка проекта
docker compose down
```
